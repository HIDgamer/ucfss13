proc
resync_airlock_apparatus
(reason, resync_physical)

One idempotent recovery point for the whole airlock cycle. Re-derives the 5 phase booleans from physical evidence (is a ship docked at inner? at outer? neither?) so they can never disagree with where the ship actually is, and always broadcasts a destination-list refresh since a resync always means availability may have changed.

resync_physical additionally snaps the turfs/effects/floodlights back to a fully-closed resting state and clears any in-flight timer/processing/autopilot-stage tracking - safe for a genuinely interrupted cycle (admin force-move, hijack, force_process(), stuck "processing" recovery), but NOT safe to run mid-way through a normal, uninterrupted sequence, since it would fast-forward past whatever step hasn't happened yet (e.g. forcing "inner closed" before the sequence's own "close inner" step has actually run). Callers on the normal internal-relocation path (on_arrival() for an expected hop) should omit it and keep relying on their own existing step-specific logic; only pass it from a path that's establishing state after something bypassed the cooperative machinery.
